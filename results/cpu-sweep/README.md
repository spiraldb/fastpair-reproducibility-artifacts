# OnPair CPU decode sweep (fat vs entries vs naive)

Cross-generational CPU measurement of the OnPair string decode, isolating the "fat
dictionary" layout that the GPU work motivated. Three byte-identical decode paths over
identical compressed columns, so the only differences are addressing and copy strategy:

- **fat** — `data + code*16`: one independent load per token, then a 16-byte over-copy
  (the layout the current `onpair` crate ships).
- **entries** — variable-stride addressing (`offset -> bytes`, a dependent load) with the
  same 16-byte over-copy. **This is the published OnPair decode** (arXiv:2508.02280).
- **naive** — variable-stride addressing + an inlined *exact* per-token copy. A
  non-over-copying baseline to ground the others; not a real codec.

`fat / entries` is the honest improvement over published OnPair (which already over-copies);
`fat / naive` shows what not over-copying at all costs. All three are asserted
byte-identical before timing. Metric is GiB/s of decoded output, at 1 / 4 / 8 threads,
on three corpora (`synthetic_url`, `tpch_comment`, `fineweb_text`), 256 MiB/column.

## Files

- `cpu-sweep.json` — the combined artifact (all machines + matrix metadata); generated by
  `combine.py`. This is what figures/analysis should read.
- `<label>/onpair_cpu.json` — per-machine results (9 rows: 3 columns × 3 thread counts).
- `<label>/RESULTS.md` — per-machine readable table.
- `<label>/cpu-env.txt` — `lscpu` + topology + (best-effort) memory type.
- `<label>/machine.meta` — label / instance type / DDR / region / bench MiB.
- `<label>/onpair_cpu_raw.tar.gz` — full provenance (json, stderr bench log, env, build log).
- Operational logs (`orchestrate.log`, `run.log`) are git-ignored.

## Reproduce

The benchmark crate is committed at [`../../experiments/bench/cpu/`](../../experiments/bench/cpu)
(depends on `onpair = "0.0.4"` from crates.io, built with `RUSTFLAGS=-C target-cpu=native`).
The sweep was driven by an orchestrator that provisions each AWS box, builds + runs the crate, and
tears it down (author-machine tooling, not shipped). To regenerate the combined json after a sweep:

```
python3 results/cpu-sweep/combine.py
```

Each box is owner-tagged and torn down automatically (one at a time, sequential).
